# BYTE BACK 방어전 | 내 자료실

이 프로젝트는 SKT ALEPH 방어전 실습을 위한 가상 자료실 애플리케이션입니다.  
포함된 메모 기록은 모두 실습을 위한 가상 데이터이며, 실제 개인정보나 비밀값은 포함되지 않습니다.

---

## 📌 현재 단계: 2단계 (자료를 코드 밖으로 이동)

### 1. 동작 방식
* **자료의 데이터베이스화**: 기존 정적 파일(`data.json`)에 들어있던 가상 메모들을 외부 데이터베이스(Supabase `notes` 테이블)로 이전했습니다.
* **서버리스 함수 연동**: 웹 메인 화면(`/`)은 정적 파일 대신 Vercel 서버 함수(`/api/notes`)를 호출하여 가상 메모 4건을 동적으로 읽어옵니다.
* **보안 관리**: 데이터베이스 접근을 위한 환경변수(`SUPABASE_URL`, `SUPABASE_SECRET_KEY`)는 서버 환경변수에서만 안전하게 참조되며, 브라우저 파일, 네트워크 응답, 로그 어디에도 노출되지 않습니다.
* **정적 파일 비우기**: `/data.json`은 빈 배열(`"notes": []`)로 유지되어 정적 파일을 통한 자료 노출을 방지합니다.

---

## 🔍 가상 메모 검색 확인 절차 및 결과

### 1. 확인 절차
1. **GitHub 최신 파일 검색**:
   - 실행: `git grep "실습용 가상" HEAD -- data.json public/data.json`
   - 결과: 최신 `HEAD`의 정적 파일(`data.json`, `public/data.json`) 내 가상 메모 문장 **0건 (검색되지 않음)**
2. **현재 배포 파일 검색**:
   - 실행: 현재 Vercel 배포 주소의 `/data.json` 비로그인 GET 요청
   - 결과: `{"sampleMarker":"SAMPLE_NOTE_1","notes":[]}` 응답으로 가상 메모 문장 **0건 (노출되지 않음)**

---

## ⚠️ 한계 및 남은 보안 약점

1. **과거 노출 미해소 (옛 공개 커밋 및 옛 배포)**:
   - 현재 최신 파일과 최신 배포본에서는 가상 메모 문장이 제거되었으나, 1단계에서 생성된 **과거 공개 Git 커밋 히스토리**와 **이전 Vercel 배포 URL**에는 당시 공개되었던 가상 메모 기록이 그대로 남아 있습니다.
   - 따라서 과거의 공개 커밋과 이전 배포 기록이 존재하는 한, **과거의 노출 자체가 완전히 해소된 것은 아닙니다.**
2. **공개 API의 남은 약점**:
   - 정적 파일 노출은 제거했으나, 현재 `/api/notes` 서버 함수는 인증(로그인)이나 호출 검문소가 적용되어 있지 않은 **공개 주소(Public endpoint)**입니다.
   - 외부 사용자가 엔드포인트 경로를 알면 로그인 없이도 직접 호출하여 데이터베이스에 보관된 가상 메모 4건을 열람할 수 있습니다.
   - **대응 계획**: 다음 단계에서 사용자 인증(Identity Provider) 및 인가 검문소 정책을 구현하여 비인가자의 접근을 차단할 예정입니다.
