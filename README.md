# BYTE BACK 방어전 | 내 자료실

이 프로젝트는 SKT ALEPH 방어전 실습을 위한 가상 자료실 애플리케이션입니다.  
포함된 메모 기록은 모두 실습을 위한 가상 데이터이며, 실제 개인정보나 비밀값은 포함되지 않습니다.

---

## 📌 현재 단계: 3단계 (진짜 로그인을 붙입니다)

### 1. 동작 방식 및 현재 작동하는 기능
* **사용자 인증 (Identity Provider)**: Supabase Auth 공식 SDK를 연동하여 이메일·비밀번호 기반 로그인/로그아웃 및 브라우저 세션 관리 UI를 구축했습니다.
* **API 토큰 검문소 연동**: 자료 API(`/api/notes`, `/api/notes/:id`)에 `src/verify-login.mjs` 검증기를 적용하여, 유효한 Bearer 토큰이 없는 요청은 즉시 `401 Unauthorized`로 차단합니다.
* **메모 CRUD REST API 및 화면**:
  - `GET /api/notes`: 로그인 사용자의 메모 목록 조회
  - `POST /api/notes`: 신규 메모 추가 (서버가 검증한 사용자 ID를 `owner_id`로 저장)
  - `GET /api/notes/:id`: 특정 메모 단건 조회 (삭제 후 조회 시 404)
  - `PUT /api/notes/:id`: 메모 수정
  - `DELETE /api/notes/:id`: 메모 삭제
* **정적 파일 보호 유지**: 비로그인 정적 파일(`/data.json`)은 빈 배열로 유지되어 정적 파일을 통한 자료 노출이 차단됩니다.

---

## 🔄 다시 실행하는 방법

1. **로컬 정적 빌드**:
   ```bash
   npm run build -- --local
   ```
2. **제출 묶음 생성 및 자기 점검**:
   ```bash
   npm run bundle
   ```
3. **배포 사이트 확인**:
   - 주소: https://choi-bujang-secret-vault-6asl.vercel.app
   - 로그인하지 않은 시크릿 창에서는 자료 및 작성 폼이 숨겨집니다.
   - A 계정 로그인 후 메모 추가, 수정, 삭제 및 로그아웃이 가능합니다.

---

## ⚠️ 한계 및 남은 보안 약점

1. **소유자 인가(Ownership Authorization) 미적용**:
   - 현재는 로그인 여부(인증)만 확인할 뿐, 단건 메모 수정(`PUT /api/notes/:id`) 및 삭제(`DELETE /api/notes/:id`) 시 요청자가 해당 메모의 소유자인지 대조하지 않습니다.
   - 따라서 B 계정이 로그인한 상태에서 A 계정의 메모 UUID를 알면 임의로 수정하거나 삭제할 수 있는 취약점이 남아 있습니다.
   - **대응 계획**: 4단계에서 소유자 검사 및 인가 검증 로직을 도입하여 타인의 메모 접근 및 변조를 차단할 예정입니다.
2. **세분화된 접근 제어 정책 부재**:
   - 역할 기반(RBAC) 또는 정책 기반 접근 제어가 적용되지 않아, 모든 로그인 사용자가 동등한 수준의 권한을 가집니다.
